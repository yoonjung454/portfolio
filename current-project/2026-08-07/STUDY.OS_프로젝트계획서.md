# STUDY.OS 프로젝트 계획서

---

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | STUDY.OS |
| 한 줄 소개 | 대학생의 '진짜 바쁜 노트북 화면'을 재현한 인터랙티브 웹사이트 |
| 유형 | 웹 기반 인터랙티브 콘텐츠 (감성/체험형 UI 아트) |
| 사용 기술 | HTML, CSS, JavaScript (Vanilla) |
| 대상 사용자 | 대학생, 취업준비생, 팀플 경험자, 일반 웹 방문자 |
| 핵심 경험 | 과제 문서, 화상회의, 팀플 메신저, LMS 알림창이 동시에 뜨는 '멀티태스킹 지옥'을 시뮬레이션 |

STUDY.OS는 실제 운영체제(OS)의 데스크톱 환경을 패러디한 웹 페이지로, 방문자가 접속하는 순간부터 과제 문서 작성 창, 온라인 화상회의(Zoom류) 창, 팀플 단체 카톡방, LMS(학습관리시스템) 알림 팝업이 순차적/동시다발적으로 화면에 나타나며 서로 겹치고 알림음이 울리는 등, 대학생이라면 누구나 공감할 "정신없이 바쁜 노트북 화면"을 그대로 재현하는 인터랙티브 웹 경험입니다.

---

## 2. 기획 배경 및 목적

### 2-1. 기획 배경

컴퓨터로 공부하거나 과제를 하다 보면 유튜브를 보거나 인터넷을 하는 등 잠깐 딴짓을 하게 되는 경우가 많다. 이때 주변에 사람이 오거나 화면을 보여줘야 하는 상황에서 빠르게 공부하고 있는 것처럼 보이고 싶을 때가 있다.

이러한 상황에서 아이디어를 얻어, 실제 대학생이 과제를 하며 바쁘게 작업하고 있는 것처럼 보이는 화면을 만들어보고자 했다. 문서 작성, 온라인 회의, 팀플 메신저, LMS 알림 등을 한 화면에 구성하고 실제로 타이핑이나 메시지 입력도 가능하게 하여 단순한 이미지가 아닌 현실감 있는 '바쁜 대학생 화면'을 구현하고자 한다.

### 2-2. 기획 목적

1. **위장용 '바쁜 화면' 제공**: 딴짓 중 누군가 다가오거나 화면을 보여줘야 할 때, 순식간에 전환해 실제로 과제·회의·팀플을 하고 있는 것처럼 보이게 함
2. **실제 조작 가능한 현실감 구현**: 단순히 정지된 이미지가 아니라 문서에 직접 타이핑하고 메신저에 실제 메시지를 입력할 수 있도록 하여 몰입도와 신뢰도를 높임
3. **인터랙티브 웹 기술 학습 및 포트폴리오화**: 다중 창 관리, 실시간 입력 처리, 드래그, z-index 등 프론트엔드 핵심 기술 실습
4. **공감 기반의 재미 요소 제공**: "이거 완전 내 얘기잖아"라는 반응을 이끌어내는 위트 있는 콘텐츠로 자연스러운 확산 유도

## 3. 주요 기능

### 3-1. 핵심 기능 목록

| 번호 | 기능명 | 설명 |
|---|---|---|
| F1 | 긴급 전환 단축키 | 특정 키(예: 스페이스바 또는 Esc)를 누르면 어떤 화면에서든 즉시 '바쁜 과제 화면'으로 전환되어, 누군가 다가오는 순간에도 빠르게 위장할 수 있음 |
| F2 | 다중 창(Window) 시스템 | 과제 문서, 화상회의, 메신저, 알림 창을 독립적인 '윈도우'로 구현, 드래그 이동 및 z-index 앞으로 가져오기 지원 |
| F3 | 과제 문서 창 (실제 타이핑 가능) | 워드/한글 프로그램을 패러디한 문서 편집 창. 사용자가 직접 키보드로 타이핑하면 실제 텍스트로 입력되어, 누가 보더라도 진짜 과제를 쓰고 있는 것처럼 보이게 함 |
| F4 | 온라인 화상회의 창 | 화상회의 UI(참가자 화면, 음소거 아이콘, 채팅창)를 패러디, 교수님/팀원 대사가 랜덤 등장, "OO님이 마이크가 꺼져있어요"류 코믹 알림 |
| F5 | 팀플 메신저(단톡방, 실제 메시지 입력 가능) | 실시간으로 메시지가 쌓이는 단체채팅 UI. 사용자가 입력창에 실제 메시지를 작성·전송할 수 있어 진짜 팀플 대화를 하는 듯한 현실감 제공, "저 오늘 못할 것 같아요" 등 팀원 대사 자동 출력도 병행 |
| F6 | LMS 알림 팝업 | "과제 마감 10분 전", "출석 미인정" 등 화면 우측 하단에서 튀어나오는 토스트/배너 알림 |
| F7 | 시간 경과 스트레스 게이지 | 시간이 지날수록 창이 많아지고 알림 빈도가 증가 → 화면이 점점 더 혼란스러워지는 난이도 상승 연출 |
| F8 | 사운드 효과 | 카톡 알림음, 줌 입장음, 키보드 타건음 등 배경 사운드로 몰입감 강화 (음소거 토글 제공) |
| F9 | 인터랙션 반응 | 창을 닫으면 새 창이 더 빨리 나타나거나, 특정 창을 오래 방치하면 재촉 알림이 뜨는 등 사용자 행동에 반응 |
| F10 | 엔딩/결과 화면 | 일정 시간 생존(?) 또는 모든 이벤트 완료 시 "오늘도 무사히 하루를 버텼습니다" 식 엔딩과 결과 공유(캡처/링크) 유도 |

### 3-2. 부가 기능 (확장 옵션)

- 반응형 대응(모바일에서는 '좁은 화면 경고' 또는 축소 버전 제공)
- 다크모드/라이트모드 전환
- 결과 화면 SNS 공유 버튼(이미지 캡처 or 문구 복사)

## 4. 화면 구성

### 4-1. 전체 플로우

```
[1] 초기 바탕화면 (평상시 대기 상태, 아이콘 및 시계만 노출)
        ↓
[2] 긴급 전환 단축키 입력 → 화면 즉시 전환 연출
        ↓
[3] '바쁜 화면' 진입 (과제 문서 + 화상회의 + 메신저 + LMS 알림 창 동시 배치)
        ↓
[4] 실시간 인터랙션 (실제 타이핑/메시지 입력, 창 드래그·이동에 반응)
        ↓
[5] 알림 심화 구간 (시간 경과에 따라 알림 빈도가 늘어나 현실감 강화)
```

### 4-2. 화면별 구성 요소

**① 초기 바탕화면**
- 상단 메뉴바: 로고, 현재 시각, 배터리/와이파이 아이콘(패러디용 장식)
- 하단 작업표시줄: 실행 중인 창 목록, 시작 버튼
- 바탕화면 아이콘: '족보.hwp', '과제_최종_진짜최종.docx' 등 밈성 파일 아이콘
- 평소에는 창이 거의 없는 조용한 상태를 유지해 자연스러운 대기 화면으로 기능

**② 창(Window) 공통 레이아웃**
- 상단 타이틀바(닫기/최소화 버튼, 드래그 핸들)
- 본문 콘텐츠 영역(창 종류별 상이)
- 그림자 및 활성/비활성 상태 시각적 구분

**③ 개별 창 UI**
- 과제 문서 창: 툴바(글꼴, 저장 아이콘) + 실제 입력 가능한 텍스트 편집 영역
- 화상회의 창: 참가자 그리드 화면 + 하단 컨트롤바(마이크, 카메라, 채팅, 나가기)
- 메신저 창: 상단 채팅방 제목 + 말풍선 리스트 + 실제 전송 가능한 입력창
- LMS 알림: 화면 모서리에서 슬라이드 인/아웃 되는 토스트 카드

## 5. 사용 기술

| 구분 | 기술 | 활용 목적 |
|---|---|---|
| 마크업 | HTML5 | 시맨틱 구조, 창/아이콘/알림 등 UI 요소 마크업 |
| 스타일 | CSS3 | 레이아웃(Flexbox/Grid), 애니메이션(@keyframes, transition), 다중 창 겹침 표현(z-index, box-shadow) |
| 로직 | JavaScript (Vanilla ES6+) | 창 생성/드래그/닫기 이벤트, 타이머 기반 알림 스케줄링, 상태(state) 관리, 사운드 재생(Audio API) |
| 기타 | 로컬 이미지/아이콘, Web Audio(효과음) | 시각적 완성도 및 몰입감 강화 |

> 별도 프레임워크 없이 순수 HTML/CSS/JS로 구현하여 로딩 속도를 가볍게 유지하고, 구현 원리를 온전히 학습·통제할 수 있도록 합니다.

## 6. 구현 방법

### 6-1. 개발 구조 설계

- `index.html` : 전체 레이아웃(초기 바탕화면 ~ 전환 ~ 창 시스템) 골격
- `style.css` : 공통 스타일 + 창/애니메이션 스타일 모듈화
- `script.js` (또는 기능별 분할: `windowManager.js`, `eventScheduler.js`, `sound.js`)

### 6-2. 핵심 구현 로직

1. **창(Window) 객체화**
   - 창마다 고유 ID, 위치(x, y), z-index를 가진 JS 객체로 관리
   - 창 생성 시 DOM에 동적으로 `<div class="window">` 추가, 클릭 시 z-index 최상단으로 갱신

2. **드래그 앤 드롭**
   - `mousedown` → `mousemove` → `mouseup` 이벤트 조합으로 타이틀바 드래그 구현
   - 모바일 대응 시 `touchstart`/`touchmove` 병행 처리

3. **이벤트 스케줄링(혼돈 연출의 핵심)**
   - `setTimeout`/`setInterval`을 활용해 시간 흐름에 따라 창/알림이 등장하는 타임라인 설계
   - 배열 기반 "이벤트 큐"를 만들어 순서/랜덤 요소를 혼합 (예: 정해진 이벤트 + 랜덤 대사 뱅크에서 추출)

4. **알림(Toast) 시스템**
   - 공통 알림 생성 함수(`showNotification(message, type)`)로 LMS/카톡 알림 등을 통일된 방식으로 호출
   - CSS 애니메이션(slide-in/out)과 자동 소멸(setTimeout) 처리

5. **난이도 상승(스트레스 게이지) 로직**
   - 경과 시간을 추적하는 전역 타이머 → 일정 구간마다 이벤트 발생 주기를 단축시키는 함수 적용

6. **사운드 처리**
   - `Audio` 객체 또는 `<audio>` 태그로 효과음 재생, 음소거 토글 버튼으로 `muted` 상태 관리

7. **반응형 처리**
   - 미디어쿼리로 소형 화면 대응, 필요 시 "PC 환경 권장" 안내 오버레이 제공

### 6-3. 개발 방식

- 단계별 프로토타입(정적 목업 → 창 시스템 → 이벤트 스케줄링 → 사운드/디테일) 순으로 점진적 구현
- 기능별 브랜치 관리 후 통합, 최종 QA 단계에서 다양한 브라우저(Chrome, Edge, Safari)에서 크로스 테스트

## 7. 기대 효과

1. **실용적인 위장 도구로서의 활용성**
   - 딴짓 중 갑작스러운 상황에서도 즉시 '바쁜 과제 화면'으로 전환해 실제로 도움이 되는 실용 콘텐츠 제공
2. **현실감 있는 인터랙션으로 공감대 형성**
   - 실제 타이핑·메시지 입력이 가능해 "이거 완전 내 얘기잖아"라는 반응을 이끌어내는 몰입형 경험 제공
3. **포트폴리오 경쟁력 강화**
   - 순수 바닐라 JS로 다중 창 관리, 실시간 입력 처리, 애니메이션을 구현함으로써 프론트엔드 기초 역량을 명확히 증명
4. **UX/인터랙션 디자인 역량 증대**
   - 단순 정보 전달형 웹이 아닌 실제 조작이 가능한 인터페이스 설계 경험 확보
5. **확장 가능성**
   - 추후 '직장인 버전(업무 화면 위장)' 등 유사 컨셉으로 시리즈화 가능
