# Portfolio — 개인 기록용 포트폴리오 사이트 기획서

전자공학과 3학년 학생이 그동안 진행한 프로젝트와 학습 과정을 정리하기 위해 만드는 개인 포트폴리오 사이트 기획서다.

회로부터 코드까지 직접 만들어보면서 남긴 기록들을 한곳에 모아두는 **개인 아카이브 + 포트폴리오** 이다. 전자공학, 하드웨어, 임베디드, 프로그래밍, AI 등 프로젝트를 하면서 자연스럽게 넓어진 관심 분야를 보여주고, 결과물뿐 아니라 그 과정에서 부딪혔던 문제와 해결 방법도 함께 남기려고 한다.

## 1. 전체 사이트 구조

사이트는 페이지 이동 없이 아래로 스크롤하면서 각 섹션을 순서대로 보여주는 **싱글 페이지(Single Page) 구조**로 만든다.

```
Navigation Bar (상단 고정)
│
├── 1. Home             — 3D 인터랙티브 히어로
├── 2. About            — 자기소개
├── 3. Current Project  — 진행중인 프로젝트 (피지컬 AI 일경험 프로젝트)
├── 4. Projects         — 프로젝트 아카이브 (9개)
├── 5. Skills           — 기술 스택
├── 6. Experience       — 교육 / 활동 / 수상
└── 7. Contact          — 연락처
```

메뉴를 클릭하면 페이지 이동 없이 해당 섹션으로 부드럽게 스크롤 이동한다. 지금 보고 있는 섹션이 어디인지에 따라 메뉴 항목이 자동으로 강조 표시되도록 만들 계획이다.

Current Project는 Projects Archive 바로 위에 배치해서, "지금 진행 중인 것"과 "이미 마무리한 것"이 시각적으로 자연스럽게 이어지도록 구성한다.

전체적으로는 "Home은 화려하고 인터랙티브하게, 나머지 섹션은 깔끔하고 읽기 편하게"라는 방향을 기본으로 잡았다. 인터랙션이 사이트의 개성이 되긴 해야 하지만, 그것 때문에 정작 프로젝트 내용을 읽기 어려워지면 안 된다고 생각한다.

## 2. Home — 3D Interactive Hero



### 2-1. 콘셉트

화면 중앙에는 **공중에 떠 있는 전자 장치 / PCB 오브젝트**를 하나 배치한다. Floating PCB, Electronic Workbench, Exploded Electronics View 같은 이미지를 참고해서, PCB 기판 위에 MCU, 센서, IC, 배선 같은 요소가 보이는 형태로 구성할 예정이다.

중앙 오브젝트 주변에는 작은 요소들을 함께 띄워둔다.

- Sensor
- MCU
- Circuit
- Code
- AI
- Embedded

이 요소들을 통해 "회로 → 하드웨어 → 코드 → AI로 이어지는 프로젝트를 만드는 사람"이라는 이미지를 자연스럽게 전달하고 싶다.

### 2-2. 마우스 인터랙션 (기본 구현)

가장 기본이 되는 구현은 **Three.js 같은 3D 라이브러리 없이, HTML + CSS + Vanilla JavaScript만으로 만드는 3D Tilt / Parallax 효과**다.

- 마우스를 오른쪽으로 움직이면 → 중앙 오브젝트가 오른쪽으로 살짝 회전
- 마우스를 위쪽으로 움직이면 → 오브젝트가 위쪽으로 살짝 기울어짐
- 주변의 작은 요소들(Sensor, MCU, Code 등)은 중앙 오브젝트보다 더 빠르게 또는 느리게 움직여서 서로 다른 레이어에 있는 것 같은 깊이감을 만든다

사용할 CSS / JS 요소는 다음과 같다.

- `perspective` — 3D 공간감을 만드는 기준값
- `transform`, `rotateX()`, `rotateY()`, `translateZ()` — 실제 회전과 깊이 표현
- `transition` — 마우스가 멈췄을 때 부드럽게 원래 각도로 돌아오는 효과
- JavaScript `mousemove` 이벤트 — 마우스 좌표를 받아서 회전 각도를 계산

즉, 실제 3D 모델링을 하는 것이 아니라 **평면 요소들을 3D 공간처럼 배치하고 마우스 좌표에 따라 각도만 바꿔주는 방식**이다. Three.js와 실제 3D 모델은 16번째 섹션(향후 확장 기능)에서 별도로 다룬다.

### 2-3. 스크롤과 연결되는 전환 효과

Home에서 아래로 스크롤하면 중앙 오브젝트가 그냥 사라지는 대신, **조립되어 있던 부품들이 하나씩 흩어지는 느낌**으로 연출하고 싶다.

```
완성된 전자 장치

      ↓ Scroll

 PCB      Sensor
     MCU
 Code        AI

      ↓

About Section
```

다만 이 효과는 난이도가 높을 수 있어서, 현실적으로 구현 가능한 단계별 방식을 함께 정리해둔다.

1. **기본안 (확실히 구현 가능)**: 스크롤 진행 정도에 따라 중앙 오브젝트가 점점 축소되면서 Fade Out, 동시에 살짝 회전. 주변 요소들은 각자 바깥쪽 방향으로 이동하면서 함께 Fade Out.
2. **발전안**: 스크롤 이벤트(또는 Intersection Observer)로 스크롤 진행률(0~1)을 계산해서, 각 요소의 `transform`과 `opacity`를 진행률에 비례하게 실시간으로 바꿔준다. 이렇게 하면 스크롤 속도에 맞춰 부품이 "흩어지는" 것 같은 인상을 줄 수 있다.

두 방식 모두 순수 CSS/JS로 구현 가능한 범위이며, 실제 구현할 때는 우선 1번 기본안으로 완성한 뒤 여유가 되면 2번으로 다듬는 순서로 진행할 계획이다.

### 2-4. Home에 들어갈 텍스트 요소

- 이름
- "전자공학과 학생" 소개 문구
- 한 줄 소개 — **추후 작성** (방향성만 참고: `From circuits to code.` / `I build ideas into systems.` 같은 톤. 아직 확정 문구는 아님)
- Projects(또는 Portfolio)로 이동하는 버튼/링크
- 아래로 스크롤하라는 표시 (예: 아래 화살표 아이콘, 살짝 위아래로 움직이는 애니메이션)

## 3. About

About은 Home의 화려한 3D 연출 다음에 나오는 만큼, 차분하게 나를 소개하는 섹션으로 구성한다. 담을 내용은 다음과 같다.

- 전자공학과 3학년이라는 것
- 전자공학과 소프트웨어를 함께 활용하는 프로젝트에 관심이 많다는 것
- 아이디어를 직접 기획하고 결과물로 만들어보는 걸 좋아한다는 것
- 기획력과 실행력이 강점이라는 것
- 프로젝트 도중 문제가 생겨도 끝까지 해결해서 마무리 짓는 성향이라는 것

Home에서 About으로 넘어올 때는 앞서 설명한 스크롤 전환 효과(오브젝트가 흩어지고 Fade Out)가 자연스럽게 이어지도록 하고, About 섹션 자체는 제목과 본문 텍스트가 아래에서 위로, 또는 Fade In으로 등장하는 정도의 차분한 애니메이션만 적용한다.

## 4. Current Project — 진행중인 프로젝트

Projects Archive는 기본적으로 **이미 마무리된 프로젝트**들을 서류철에 정리해두는 공간이다. 그런데 지금 한창 진행 중인 프로젝트(피지컬 AI 일경험 프로젝트)를 그 안에 그냥 같이 넣어두면, 끝난 기록들 사이에 미완성 프로젝트가 섞여서 오히려 어색해 보일 것 같았다. 그래서 Archive 바로 위에 **지금 진행 중인 프로젝트만 별도로 보여주는 섹션**을 하나 추가하기로 했다.

### 4-1. 이 섹션을 따로 두는 이유

- 방문자 입장에서 "지금 무엇을 하고 있는 사람인지"를 가장 먼저 보여줄 수 있다.
- 아직 완료되지 않은 프로젝트이기 때문에, 완결된 기록인 Archive와 디자인 톤을 구분하고 싶다.
- 프로젝트가 끝나면 이 섹션의 내용을 정리해서 Projects Archive 쪽으로 옮기고, Current Project 자리는 그다음 진행 중인 프로젝트로 교체하는 식으로 계속 갱신할 계획이다.

### 4-2. 디자인 방향

Projects Archive가 "닫혀 있는 서류철 파일"이라면, Current Project는 **아직 닫히지 않고 책상 위에 펼쳐져 있는 파일 / 진행 중인 보드** 같은 느낌으로 구분한다.

- `IN PROGRESS` 같은 배지(Badge)를 눈에 띄게 표시
- 진행 상태를 보여주는 요소 (예: 현재 단계 텍스트, 또는 간단한 진행률 바)
- Archive의 정적인 탭 UI와 달리, 살짝 강조되는 느낌의 은은한 애니메이션(예: 배지가 천천히 깜빡이거나 테두리가 은은하게 빛나는 정도)을 적용해서 "지금도 진행 중"이라는 인상을 준다
- 다만 과하게 화려한 효과보다는 Home의 3D 인터랙션과 겹치지 않는 선에서, 차분하지만 눈에 띄는 정도로만 구성

### 4-3. 표시할 내용

- 프로젝트명: 피지컬 AI 일경험 프로젝트
- 참여 형태 / 소속 기관·프로그램명: **작성 예정**
- 진행 기간: 시작일 ~ 진행중 (종료일 없이 "진행중" 표시)
- 프로젝트 개요 (한 줄 소개): **작성 예정**
- 담당 역할: **작성 예정**
- 사용 중인 / 사용 예정 기술: **작성 예정**
- 현재까지 진행 상황: 짧은 로그(day/week 단위 기록) 형태로 정리 예정
- 앞으로의 계획: **작성 예정**
- GitHub 링크: 저장소가 준비되면 연결 (현재는 placeholder)

### 4-4. 구현 방식

새로운 기술이 필요한 영역은 아니고, 앞서 정리한 스크롤 애니메이션(등장 효과)과 File Folder UI 스타일을 그대로 재활용해서 구현할 수 있다. 차이가 있다면 `is-in-progress` 같은 class를 하나 추가해서, 배지 표시나 은은한 강조 애니메이션 정도만 CSS로 다르게 적용해주는 수준이다. 즉 별도의 새 기술 없이 **기존 CSS/JS 구조 위에 상태 표시만 얹는 방식**으로 충분히 구현 가능하다.

## 5. Projects Archive

총 **9개의 프로젝트**를 보여줄 예정이다. 이 부분은 이번 사이트에서 Home 다음으로 신경 쓰고 싶은 영역인데, 일반적인 카드 Grid 대신 **서류철(파일 캐비닛)에서 프로젝트 파일을 한 장씩 꺼내보는 느낌**으로 만들고 싶다.

참고하는 이미지 키워드는 File Folder Tab UI, File Cabinet UI, Stacked Folder Tabs, Index Card Interface, Folder Tab Hover Animation 등이다.

Home이 "전자공학 / 기술 / 인터랙티브"한 느낌이라면, Projects는 "내가 진행한 프로젝트들을 모아둔 기록 보관함" 느낌으로 톤을 다르게 가져갈 생각이다. 같은 사이트 안에서 섹션마다 분위기가 조금 달라도, 오히려 Home = 미래적인 도입부 / Projects = 실제 기록 보관소 라는 구분이 명확해져서 괜찮다고 판단했다.

### 5-1. 기본 화면 — 겹쳐진 파일 탭

- 짧은 태그 (예: `#Arduino` `#센서` 형태)

## 6. Project Hover / Click Interaction

### 6-1. Hover — 파일이 살짝 빠져나오는 효과

마우스를 특정 프로젝트 탭 위에 올리면, 그 파일만 서류철에서 살짝 앞으로 빠져나온 것처럼 보이게 한다.

- 탭이 위쪽 또는 옆쪽으로 살짝 이동
- `z-index`를 높여서 다른 탭 위로 겹쳐 보이게 함
- 프로젝트 제목 강조 (색상/굵기 변화)
- 탭이 조금 더 펼쳐지는 느낌의 크기 변화
- 자연스러운 `transition`으로 위 변화들이 부드럽게 일어나도록 함

사용하는 CSS는 `:hover`, `transform`, `translate`, `transition`, `z-index` 정도로, 모두 지금까지 배운 범위 안에서 구현 가능하다.

### 6-2. Click — 파일을 꺼내서 펼쳐보는 상세 화면

탭을 클릭하면 그 프로젝트를 실제로 꺼내서 펼쳐보는 것 같은 느낌으로 상세 내용이 나타난다. 새 페이지로 이동하는 대신, **같은 페이지 안에서 JavaScript로 상세 영역을 열고 닫는 방식**을 기본으로 한다.

구현 방식 후보:

- 클릭한 탭 아래쪽에 상세 영역이 펼쳐지는 방식 (아코디언과 비슷한 구조)
- 또는 화면에 별도의 Project Detail 영역이 나타나는 방식 (오버레이/모달과 비슷한 구조)

두 방식 모두 JavaScript `click` 이벤트로 대상 프로젝트를 확인하고, 해당 요소에 `is-open` 같은 class를 추가/제거하면서 CSS `transition`으로 펼쳐지고 닫히는 애니메이션을 주는 식으로 구현한다. 이미 배운 이벤트 처리 + class 조작 방식으로 충분히 만들 수 있는 수준이라고 판단했다.

### 6-3. 프로젝트 상세 내용 항목

각 프로젝트를 클릭했을 때 보여줄 항목은 다음과 같다.

- 프로젝트 이름

## 10. 스크롤 애니메이션

스크롤 애니메이션은 이 사이트에서 인터랙션 다음으로 중요한 요소다. 다음 기능들을 포함할 계획이다.

- 각 섹션 진입 시 자연스럽게 등장하는 효과
- 제목이 아래에서 위로 올라오며 등장
- 설명 텍스트 Fade In
- Skills 항목들이 순차적으로 하나씩 등장
- Current Project 진입 시 배지 및 상태 요소가 은은하게 강조되며 등장
- Projects 진입 시 파일 탭들이 순서대로 등장
- 현재 스크롤 위치에 따라 Navigation 메뉴가 자동으로 활성화
- Navigation 클릭 시 Smooth Scroll로 이동
- Home의 3D 오브젝트에서 About으로 넘어가는 전환 효과

이 기능들은 대부분 **Vanilla JavaScript의 `IntersectionObserver`**를 기반으로 구현한다. 각 섹션(또는 섹션 안의 요소)이 화면에 들어오는 시점을 감지해서 `visible` 같은 class를 추가하고, 실제 등장 애니메이션은 CSS `transition` / `animation`으로 처리하는 방식이다. Navigation 활성화도 같은 방식으로, 현재 화면에 보이는 섹션이 무엇인지 감지해서 해당 메뉴에 `active` class를 붙이는 식으로 구현할 수 있다.

## 14. 구현 가능 여부

기획한 기능들이 지금까지 배운 HTML / CSS / JavaScript 범위 안에서 실제로 구현 가능한지 기능별로 정리했다.

| 기능 | HTML | CSS | JS | 구현 가능 여부 |
|---|---|---|---|---|
| Home 3D Tilt | 필요 | 필요 (`perspective`, `transform`) | 필요 (`mousemove`) | 가능 — CSS 3D Transform 기반 |
| Mouse Interaction | - | 필요 (`transform`, `transition`) | 필요 (`mousemove`, 좌표 계산) | 가능 |
| Parallax (주변 요소) | 필요 | 필요 (`transform`) | 필요 (요소별 이동 비율 계산) | 가능 |
| Scroll Animation | 필요 | 필요 (`transition`, `animation`) | 필요 (`IntersectionObserver`) | 가능 |
| Smooth Scroll | 필요 (앵커 링크) | 필요 (`scroll-behavior: smooth` 또는 JS 처리) | 필요 시 (`scrollIntoView`) | 가능 |
| Navigation 활성화 | 필요 | 필요 (`.active` 스타일) | 필요 (`IntersectionObserver`) | 가능 |
| Current Project 상태 배지 | 필요 | 필요 (배지 스타일, 은은한 강조 애니메이션) | 선택 (없어도 동작, 있으면 강조 연출 추가) | 가능 |
| File Folder UI | 필요 | 필요 (레이아웃/겹침 구조) | - | 가능 |
| Folder Hover Animation | - | 필요 (`:hover`, `transform`, `z-index`) | - | 가능 |
| Project Click Interaction | 필요 | 필요 (`transition`) | 필요 (`click` 이벤트) | 가능 |
| Project Detail Open/Close | 필요 | 필요 (펼침 애니메이션) | 필요 (class 추가/제거) | 가능 |
| 프로젝트 이미지 표시 | 필요 (`img`) | 필요 (사이즈/레이아웃) | - | 가능 |
| Skills 섹션 | 필요 | 필요 (카테고리별 레이아웃, 순차 등장 스타일) | 필요 시 (`IntersectionObserver`로 순차 등장) | 가능 |
| Contact 링크 | 필요 (`a` 태그) | 필요 (스타일) | - | 가능 |
| 반응형 디자인 | 필요 | 필요 (미디어 쿼리) | - | 가능 |

특히 강조하고 싶은 부분은, **실제 3D 모델(예: Three.js로 만든 PCB 모델)을 사용하지 않아도, CSS `perspective`와 `transform`만으로 충분히 "3D처럼 보이는" Home 화면을 만들 수 있다는 점**이다. 실제로는 평면 요소들을 3D 공간에 배치하고 마우스 좌표에 따라 회전각만 계산해서 바꿔주는 방식이라, 지금까지 배운 CSS/JS 지식만으로도 이번 기획의 핵심 인터랙션을 구현할 수 있다고 판단했다.

## 15. 구현 범위 및 제한사항

아래 기능들은 서버 또는 데이터베이스가 필요하기 때문에, 이번 정적 웹사이트 범위에서는 제외한다.

- 회원가입
- 로그인
- 사용자별 정보 저장
- 관리자 페이지
- 프로젝트 내용을 서버에서 자동으로 불러오기
- Contact 문의 내용을 DB에 저장하는 기능

이 기능들이 제외되는 이유는 간단하다. 이 사이트는 HTML / CSS / JavaScript만으로 동작하는 **정적 웹사이트**이기 때문이다. 회원가입이나 로그인은 사용자 정보를 어딘가에 저장하고 검증하는 과정이 필요한데, 이건 서버와 데이터베이스가 있어야 가능한 기능이다. 마찬가지로 Contact Form에 입력한 문의 내용을 저장하려면 그 데이터를 받아서 처리할 서버가 필요하다. 지금 단계에서는 이런 백엔드 없이, 브라우저에서 실행되는 코드만으로 완성할 수 있는 사이트를 만드는 것이 목표이기 때문에 위 기능들은 이번 범위에서 명확히 제외한다.

같은 이유로, Current Project 섹션의 진행 상황도 실시간으로 자동 갱신되지는 않는다. 새로운 진행 내용이 생기면 `index.html`을 직접 수정해서 업데이트하는 방식으로 운영할 계획이다.
